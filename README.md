# PlanetWar

Сезонная MMO-4X стратегия в реальном времени. Собственный движок на C++20,
пять платформ, серверная авторитетная симуляция, ноль pay-to-win.

> **Статус: Фаза 1 в работе.** Фаза 0 закрыта: ядро, платформа, Vulkan,
> первый кадр. Сейчас — ECS и тик симуляции; дальше галактика, сеть
> и headless-сервер (см. [дорожную карту](docs/05-ROADMAP.md)).

## Что это

Космическая 4X-стратегия в духе Stellaris, но соседние империи — живые люди,
а исход партии определяют билды, доктрины, логистика и дипломатия, а не донат
и не количество часов, проведённых онлайн.

Галактика практически безгранична: содержимое систем вычисляется из сида, а не
хранится, поэтому нагрузка на сервер масштабируется от числа онлайн-игроков, а не
от размера вселенной.

## Проверки, которые держат архитектуру

Правила проекта проверяются машиной, а не дисциплиной:

| Что проверяется | Чем |
|---|---|
| Симуляция считает одинаково на x86 и ARM | `pw_determinism_check`, сверка хеша с эталоном |
| `pw_sim` не зависит ни от чего, кроме `pw_core` | `tools/check_layering.sh` |
| В `pw_sim` нет плавающей точки | `tools/check_layering.sh` |
| SDL и Vulkan не просачиваются в интерфейс `pw_platform` | `tools/check_layering.sh` |
| Кадр рисуется правильно | `pw_render_tests` на программном растеризаторе |
| Компоненты не содержат ни плавающей точки, ни байтов выравнивания | `static_assert` при регистрации |
| Симуляция воспроизводится тик в тик | `pw_sim_tests`, сверка хешей мира |
| Таблицы тригонометрии и SPIR-V совпадают со своими генераторами | CI |

## Проверить, что всё работает

```
./tools/verify.sh
```

Собирает ядро и клиент, гоняет тесты, сверяет хеш детерминизма симуляции
и отрисовывает кадр. Пресет выбирается по системе — Linux, macOS на Apple
Silicon и macOS на Intel. Пропущенная проверка не считается пройденной:
пропуски перечисляются отдельным списком.

Если репозиторий склонирован без подмодулей:
`git submodule update --init --recursive`.

### Зависимости для графики

Blender для запуска игры НЕ нужен: испечённые атласы и шрифт лежат
в репозитории. Он нужен, только если вы правите модели.

```
# macOS
brew install cmake ninja vulkan-headers vulkan-loader molten-vk glslang
brew install vulkan-validationlayers      # необязательно, но полезно

# Ubuntu/Debian
sudo apt install cmake ninja-build libvulkan-dev glslang-tools mesa-vulkan-drivers
# полный список пакетов SDL — в .github/workflows/ci.yml
```

**`vulkan-loader` на маке обязателен.** Apple не поставляет Vulkan вовсе:
`vulkan-headers` даёт заголовки, `molten-vk` — реализацию поверх Metal,
а `vulkan-loader` связывает их вместе и позволяет подключать слои проверки.
Без загрузчика `find_package(Vulkan)` не находит `libvulkan` и сборка клиента
не настраивается.

Ядро и сервер собираются **без всего этого** — им не нужны ни SDL, ни Vulkan.

## Посмотреть на галактику

```
./build/dev/bin/pw_galaxy --systems 500 --out galaxy.png
```

```
./build/dev/bin/pw_galaxy --systems 500 --route 12 480 --out route.png
```

Генерирует карту, печатает статистику и рисует её в PNG. Второй вызов
подсвечивает маршрут флота и печатает время в пути. Ни видеокарты,
ни SDL не нужно. Параметры формы (`--arm-percent`, `--lanes`, `--spread`)
позволяют мерить, как решения по форме влияют на диаметр карты в прыжках
и на среднюю степень вершины — то есть на темп войны и на число горлышек.

## Сыграть

Сначала собрать. Одной командой, она же всё проверит:

```
./tools/verify.sh
```

Клиент окажется в `build/client/bin/`. Если нужен только он, без остальных
проверок:

```
cmake -S . -B build/client -G Ninja -DCMAKE_BUILD_TYPE=Release \
      -DPW_BUILD_CLIENT=ON -DPW_BUILD_TESTS=ON
cmake --build build/client -j
```

Сервер и клиент — два отдельных исполняемых файла. Сервер собирается
**без графических зависимостей**: ни SDL, ни Vulkan ему не нужны.

```
# терминал 1 — сервер
./build/client/bin/pw_server --systems 200 --players 8

# то же, но игровое время в двадцать раз быстрее — чтобы посмотреть,
# как разворачивается партия, не ожидая шесть минут за каждую проверку
./build/client/bin/pw_server --systems 200 --speed 20

# терминал 2 — клиент с окном
./build/client/bin/pw_game_client --name Михаил
```

Видов два, и у них разные вопросы. **Карта галактики** отвечает «куда
двинуть флот», **вид системы** — «что делать с этой планетой».

**Всё делается мышью.** Ни одно действие в игре не требует знать клавишу:
выбрать систему, войти в неё, выбрать планету и слот, построить здание,
заказать корабль, отправить флот, вернуть камеру, выйти из игры — всё это
кнопки и карточки на экране. Клавиши есть, но они только ускоряют то,
что и так лежит под курсором.

| Мышь | Что делает |
|---|---|
| левая по звезде | выбрать систему |
| двойной щелчок по звезде | открыть систему в объёме |
| левая по планете в объёме | выбрать планету |
| левая по строке в панели | то же самое, но списком |
| левая по пустому слоту | открыть палитру построек |
| левая по занятому слоту | показать здание и кнопку сноса |
| правая | тянуть карту, в системе — вращать камеру |
| колесо | приблизить |
| наведение | подсказка: что это и сколько стоит |

| Клавиша | Ускоряет |
|---|---|
| `Escape` | снять приказ, выйти из системы |
| `Enter` | войти в выбранную систему и обратно |
| `Tab` | следующая планета системы |

Экран собран в два столбца, и порядок в них — это порядок, в котором
человек думает. Слева сверху вниз: **система** (чья, сколько планет,
кнопка «Открыть систему») и под ней **планета** (слоты застройки, палитра
построек, ход стройки). Справа — **флот**: что стоит в системе, кнопка
«Отправить флот» и заказ кораблей. Сверху ресурсы и связь, по центру
новости, внизу полоса с «Показать всё», подсказкой и выходом.

### Первые пять минут

Порядок не случайный: экономика в игре цепочная, и половина действий
не сработает, пока не сделано предыдущее.

1. **Найдите свой дом.** При входе камера уже стоит над ним, а в новостях
   написано, какая система ваша. В левой панели — её планеты.
2. **Откройте систему** — кнопка «Открыть систему» под списком планет
   или двойной щелчок по звезде. Станет видно, чем вы владеете.
3. **Постройте шахты.** Щёлкните планету, потом пустой слот со знаком
   «+» — откроется палитра. Выберите шахту. Минералы — основа всего,
   без них не будет сплавов.
4. **Постройте литейную.** Она превращает минералы в сплавы, и это
   ЕДИНСТВЕННЫЙ их источник. Без неё флот строить не на что.
5. **Постройте верфь.** Без верфи система не строит корабли вовсе:
   вместо кнопок заказа панель честно покажет «нужна верфь».
6. **Закажите корабль** — кнопки в правой панели. Он появится, когда
   накопятся сплавы.
7. **Отправьте флот.** Выберите флот в правой панели, нажмите «Отправить
   флот» и щёлкните систему на карте. Флот пойдёт туда и начнёт занимать
   её планеты.

Наведите курсор на любую кнопку — подсказка скажет, что она делает,
сколько это стоит и почему сейчас недоступно.

**Здание не появляется по щелчку.** Шахта строится две минуты, верфь —
почти семь; в панели видно, что именно строится и на сколько процентов,
а в самом слоте идёт полоса. Заказать можно четыре здания подряд — они
встанут в очередь. Стройку видно и в объёме: постройка растёт
на поверхности планеты вместе с готовностью.

**Захватывают планеты, а не системы.** Флот берёт их по одной, от звезды
наружу: три минуты на планету. Система с четырьмя планетами — двенадцать
минут плюс перелёт. Половину системы можно взять и удержать, а сосед
останется на дальней орбите. Если хочется посмотреть быстрее, поднимите
сервер с `--speed 20`.

Без графики играть тоже можно — этим проверяется, что цикл замкнут:

```
./build/dev/bin/pw_bot --name бот --seconds 600
```

Бот застраивает столицу, заказывает корабли и расширяется. Первый захват
занимает около шести минут: прыжок между системами ~70 секунд плюс пять
минут на занятие ничьей системы.

Карта рисуется и **без окна** — тем же кодом, что и на экране:

```
./build/client/bin/pw_game_client --shot galaxy_map.png --shot-after 4
./build/client/bin/pw_game_client --shot near.png --shot-zoom 9   # крупный план
./build/client/bin/pw_game_client --shot system.png --shot-system # вид системы
```

Ради этого режима он и написан: так карта проверяется автотестом в CI,
а не глазами и не тогда, когда кто-то удосужился посмотреть.

## Посмотреть на первый кадр

```
./build/client/bin/pw_triangle                       # окно
./build/client/bin/pw_triangle --out frame.png       # без окна, в файл
```

Безголовый режим рисует в память, без дисплея и без видеокарты. Ради него
он и написан: именно так CI проверяет графику автотестом на каждом коммите,
а не «когда кто-то удосужился посмотреть».

### Ассеты

```
python3.13 -m venv .venv && .venv/bin/pip install bpy
.venv/bin/python tools/blender/build_assets.py --quality preview
```

Blender подключается как модуль, отдельный бинарь и GPU не нужны. Версия
Python важна: колёса `bpy` собраны под одну конкретную (5.2.x — Python 3.13,
4.5 LTS — Python 3.11), поэтому нужно отдельное окружение. На выходе —
спрайтовые атласы в `assets/build/`. Подробности в
[07-ASSET-PIPELINE.md](docs/07-ASSET-PIPELINE.md).

## Ключевые принятые решения

1. **Сезоны 8–12 недель** вместо вечной вселенной — лечит снежный ком, даёт честный замер скилла.
2. **2.5D рендер** — карта в плоскости, спрайты с инстансингом. Летает на телефонах.
3. **Тонкий слой зависимостей** — движок свой, готовое берём только там, где писать своё бессмысленно.
4. **Экономика на слотах и специализации** — глубина из логистики и цепочек, а не из микроменеджмента планеты.
5. **Детерминированная fixed-point симуляция** — общий код клиента и сервера, реплеи, валидация как античит.
6. **Модели в Blender, пре-рендер в спрайты** — картинка 3D-качества при стоимости отрисовки 2D. Вектора в графике игры нет.
7. **Один бэкенд Vulkan** вместо Vulkan плюс Metal — на Apple поверх Metal через MoltenVK. Графический слой пишется один раз, а не два.
8. **Безголовый рендер как обязательный режим** — графика проверяется автотестом в CI на машине без дисплея и без видеокарты.
