# 02 — Архитектура движка

## Модульная структура

Каждый модуль — отдельная статическая библиотека. Зависимости строго
направленные, циклы запрещены на уровне CMake.

```
pw_core       Аллокаторы (arena / pool / stack), job system (work stealing),
              математика (fixed-point + float), SoA-контейнеры, сериализация,
              логирование, интеграция с профайлером.
                 зависит от: —

pw_platform   Окно, ввод, файловая система, потоки, время, сокеты.
                 зависит от: pw_core

pw_rhi        Абстракция GPU. Backend'ы: Vulkan, Metal.
                 зависит от: pw_core, pw_platform

pw_render     2.5D-рендер: инстансинг звёзд и флотов, батчинг гиперлиний,
              SDF-текст, пост-обработка.
                 зависит от: pw_core, pw_rhi

pw_ui         Data-bound UI, единый для мыши и тача, layout-движок.
                 зависит от: pw_core, pw_render

pw_sim        ECS и вся игровая логика.
                 зависит от: pw_core   ← и БОЛЬШЕ НИ ОТ ЧЕГО

pw_net        Транспорт, сериализация пакетов, delta-снапшоты, AOI.
                 зависит от: pw_core, pw_platform

pw_data       Схемы, загрузка баланса, хот-релоад, кодогенерация.
                 зависит от: pw_core

pw_editor     ImGui-инструменты: инспектор, редактор баланса, аналитика,
              билд-пайплайн. Только десктоп, в релизный клиент не входит.
                 зависит от: всё, кроме себя

--- приложения ---

pw_client     core + platform + rhi + render + ui + sim + net + data
pw_server     core + platform + sim + net + data          (headless)
pw_tools      pw_client + pw_editor                       (dev-сборка)
```

### Главное правило архитектуры

> **`pw_sim` не зависит ни от чего, кроме `pw_core`.**

Из этого следует всё остальное:

- Сервер собирается headless — без GPU, без окна, без SDL-видео
- Симуляцию можно гонять в юнит-тестах и в CI без видеокарты
- Клиент и сервер исполняют **буквально один и тот же код правил** — расхождение
  баланса между ними технически невозможно
- Реплеи и валидация боёв работают из коробки
- Ночной прогон целого сезона на ботах — это просто `pw_server` без сети

## Детерминизм

Симуляция обязана давать бит-в-бит одинаковый результат на x86 и ARM, на всех
пяти платформах, при любом уровне оптимизации. Это фундамент для клиентского
предсказания, реплеев и античита.

### Правила

**Никакого `float` и `double` внутри `pw_sim`.** Вся игровая математика — на
fixed-point: `fixed64` (Q32.32) для позиций и накоплений, `fixed32` (Q16.16) для
множителей и процентов. Float остаётся только в рендере и UI, где детерминизм не
нужен.

**Свои трансцендентные функции.** `sqrt`, `sin`, `cos`, `atan2` реализуются через
таблицы с линейной интерполяцией. Стандартная библиотека даёт разные результаты
на разных платформах и потому запрещена в `pw_sim`.

**Явная случайность.** PRNG — PCG32 с явным сидом. У каждой подсистемы свой
независимый поток случайности, чтобы порядок вызовов одной подсистемы не влиял на
результаты другой.

**Стабильный порядок итерации.** Проход по сущностям — всегда по плотному индексу.
Итерация по хеш-таблице или по адресам указателей запрещена: их порядок зависит от
раскладки памяти.

**Компилятор.** `-ffast-math` и подобное запрещены для `pw_sim`. Целочисленная
арифметика с определённым поведением при переполнении.

### Проверка

CI-задача `determinism_check`: одна и та же последовательность из ~50 000 команд
прогоняется на Linux/x86-64, Windows/x86-64, macOS/arm64 и Android/arm64. Хеш
состояния мира после каждой 1000 тиков должен совпасть побайтово. Расхождение —
красный билд, а не «предупреждение».

## ECS

Своя реализация, **archetype-based, данные в SoA**. Для нашего профиля нагрузки
(десятки тысяч однотипных сущностей, полный проход по компоненту на каждом тике)
это заметно выигрывает у sparse-set: проход линеен по памяти и векторизуется.

Ожидаемые компоненты:

```
Position          координата в галактике (fixed64)
SystemRef         в какой системе находится
OwnerEmpire       чья сущность
PlanetClass       класс планеты (детерминирует слоты)
PlanetSlots       что построено в слотах
Specialization    специализация планеты
ProductionState   накопления, очередь производства
FleetComposition  состав флота: корпуса и модули
FleetOrders       текущий приказ и постоянные приказы
Movement          маршрут по графу гиперлиний, прогресс
SiegeState        прогресс осады, если планета осаждается
ConvoyRoute       маршрут конвоя, груз
Visibility        кто эту сущность видит (для тумана войны)
```

Системы тика упорядочены явным графом зависимостей и распараллеливаются джоб-системой
там, где не конфликтуют по компонентам.

## Рендер (2.5D)

Целевой бюджет: **60 FPS при 5000 видимых объектов на телефоне четырёхлетней
давности.**

Достигается за счёт того, что вся сцена рисуется единицами draw call:

- **Звёзды и планеты** — один инстансированный вызов на все видимые объекты.
  Инстанс-буфер: позиция, размер, цвет, индекс в атласе.
- **Гиперлинии** — инстансированные quad'ы, а не примитивы линий. Даёт стабильную
  толщину при любом зуме и корректное сглаживание; аппаратные линии этого не
  умеют.
- **Флоты и иконки** — тот же инстансинг, отдельный атлас.
- **Текст** — SDF-атлас. Кириллица и латиница обязательны с первого дня, CJK
  закладывается в формат атласа.
- **Пост-обработка** — bloom для звёзд, лёгкий tone mapping. Отключаемо на слабых
  устройствах.
- **UI** — ортогональная проекция поверх сцены.

Камера: ортографическая с параллаксными слоями фона. «2.5D» здесь означает
плоскую карту с глубиной слоёв, а не 3D-сцену.

## Платформенный слой

Один и тот же C++ код, различия изолированы в `pw_platform` и в точке входа:

| Платформа | Точка входа | Графика | Упаковка |
|---|---|---|---|
| Windows | `WinMain` | Vulkan | `.exe` + зависимости, инсталлятор |
| Linux | `main` | Vulkan (X11/Wayland через SDL) | AppImage |
| macOS | `main` | Metal | `.app` bundle, нотаризация |
| Android | NativeActivity через SDL | Vulkan | Gradle → `.aab` |
| iOS | UIKit через SDL | Metal | Xcode-проект генерируется CMake |

**OpenGL не используется вообще.** Он объявлен устаревшим на платформах Apple, и
поддерживать его ради совместимости со старым железом дороже, чем поднять
минимальные требования до Vulkan 1.1 / Metal 2.

## Зависимости

Политика — **тонкий слой**: всё, что относится к игре, пишем сами; готовое берём
только там, где писать своё не даёт ничего, кроме потерянных месяцев.

| Библиотека | Зачем | Лицензия |
|---|---|---|
| SDL3 | Окно, ввод, аудио на всех пяти платформах | Zlib |
| Vulkan-Headers + volk | Загрузчик Vulkan | Apache 2.0 / MIT |
| VulkanMemoryAllocator | GPU-аллокатор | MIT |
| Dear ImGui | Редактор. **В релизный клиент не входит** | MIT |
| stb_image, stb_truetype | Декод картинок, растеризация шрифтов для SDF-атласа | MIT / public domain |
| zstd | Сжатие снапшотов и ассетов | BSD |
| Tracy | Профайлер, только dev-сборки | BSD |
| doctest | Юнит-тесты | MIT |

Что мы **пишем сами**, потому что это и есть движок: ECS, симуляция, сетевой
слой, рендер, UI-фреймворк, редактор, система сборки ассетов, система данных.

Правила вендоринга: всё в `third_party/` как git submodule на фиксированном теге,
собирается нашим CMake. Ни одного бинарного блоба, ни одной GPL-зависимости, ни
одного пакетного менеджера в цепочке сборки.

**Почему SDL3, а не свой платформенный слой.** Собственный слой для
Windows/Linux/macOS реалистичен. Собственный слой для Android NDK и iOS UIKit —
это дополнительные 6–12 месяцев до первого пикселя на телефоне, и эта работа
никак не отличает нашу игру от других. SDL3 покрывает все пять платформ, лежит у
нас в исходниках, собирается нашей системой сборки и в любой момент может быть
заменён — интерфейс `pw_platform` специально спроектирован так, чтобы SDL не
протекал наружу.

## Система сборки

CMake 3.25+ с пресетами. Один `CMakePresets.json` описывает все конфигурации:

```
linux-x64-debug        linux-x64-release
windows-x64-debug      windows-x64-release
macos-arm64-release    macos-x64-release
android-arm64-release
ios-arm64-release
server-linux-x64-release      (headless, без rhi/render/ui)
```

Внешние ограничения, которые нельзя обойти:

- **macOS и iOS собираются только на Mac** — нужен Xcode и компилятор Metal-шейдеров
- **iOS требует Apple Developer Program** — 99 USD в год, иначе сборку нельзя
  поставить даже на своё устройство дольше чем на 7 дней
- **Android требует NDK**, но собирается с любой ОС

## CI

GitHub Actions:

- **На каждый коммит:** сборка Linux + Windows + Android, юнит-тесты,
  `determinism_check`, статический анализ (clang-tidy), проверка форматирования
- **Ночью:** прогон полного сезона на ботах в ускоренном режиме, отчёт по балансу
  (см. [04](04-EDITOR-AND-TOOLS.md)), нагрузочный тест сервера
- **На релизных тегах:** дополнительно macOS и iOS (раннеры дороже, поэтому не на
  каждый коммит)
