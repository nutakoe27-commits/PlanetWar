# 04 — Редактор и инструменты

Требование: **владелец проекта самостоятельно настраивает баланс и собирает игру
под все платформы, не притрагиваясь к коду.**

Редактор — это отдельное приложение `pw_tools` (движок + слой `pw_editor` на
Dear ImGui). Только десктоп. **В релизный клиент не входит** — ни байта редактора
не попадает игроку.

## Схемо-ориентированный подход

Ключевая идея: **UI редактора не пишется руками.** Он генерируется из описания
данных.

### Как это работает

Есть файл схемы, например `schemas/ship_hull.pws`:

```
schema ship_hull {
    id            : string   key
    display_name  : loc_string
    class         : enum { corvette, destroyer, cruiser, battleship }
    hull_points   : fixed    range=[100, 100000]  unit=hp
    base_speed    : fixed    range=[0, 500]       unit=au_per_day
    weapon_slots  : int      range=[0, 16]
    defense_slots : int      range=[0, 16]
    utility_slots : int      range=[0, 16]
    alloy_cost    : fixed    range=[0, 50000]     unit=alloys
    upkeep_energy : fixed    range=[0, 1000]      unit=energy_per_day
}
```

Из одной схемы генерируется **всё сразу**:

1. **C++ структура** и типобезопасный доступ к данным
2. **Парсер и сериализатор** таблиц баланса
3. **Схема сетевых пакетов**, если тип реплицируется
4. **UI редактора** — таблица с колонками, слайдерами по указанным диапазонам,
   выпадающими списками для enum, подсказками с единицами измерения
5. **Валидатор** — проверка диапазонов при загрузке, отказ грузить битые данные

Добавили в схему поле `point_defense_range : fixed range=[0,100] unit=au` — и в
редакторе сам появился слайдер, в коде само появилось поле, в таблицах баланса
сама появилась колонка. **Ноль ручной работы, ноль возможности рассинхронизации.**

### Формат данных баланса

Таблицы хранятся как **текст** (табличный формат, по строке на запись) —
чтобы они нормально жили в git: видимый diff, работающий merge, история изменений
баланса как история коммитов.

## Живой цикл настройки

1. Кнопка **Play Local** — редактор поднимает локальный `pw_server` и
   подключает к нему клиент в соседней панели
2. Открываешь таблицу баланса, двигаешь число
3. **Хот-релоад**: сервер перезагружает данные без рестарта, симуляция
   продолжается с того же места
4. Сразу видишь эффект — и в игре, и на графиках

Цикл «изменил число → увидел результат» занимает секунды, а не минуты.

## Аналитика — то, что реально решает баланс

Ручная настройка чисел не даёт сбалансированной игры. Нужны инструменты, которые
**доказывают**, что доминирующей стратегии нет.

### Симулятор боя

Задаёшь два билда флота → 1000 прогонов с разными сидами → распределение исходов.

Показывает:
- Процент побед каждой стороны
- Средние потери
- **Матрицу контр-билдов**: таблица «билд A против билда B» по всем парам

Здоровая матрица — та, где у каждого билда есть и жертва, и хищник. Строка, где
билд выигрывает у всех, — это сломанный баланс, видимый сразу, а не через месяц
жалоб игроков.

### Экономический солвер

Строит математически оптимальный порядок постройки для заданной цели
(«максимум сплавов к 14-му дню», «максимум исследований к 30-му»).

Даёт два ответа:
- Каков потолок экономики — с чем сравнивать живых игроков
- **Есть ли единственная оптимальная стратегия.** Если солвер всегда выдаёт один
  и тот же порядок с большим отрывом — баланс сломан, выбора у игрока нет.

### Прогон сезона на ботах

Ускоренная симуляция полного сезона с N ботами разных архетипов. Отчёт:

- Распределение престижа по трекам — не доминирует ли один трек
- Кривая роста лидера против медианы — насколько силён снежный ком
- Частота использования каждой технологии, корпуса, специализации —
  **что никогда не используется, то мёртвый контент**
- Влияние времени онлайн на результат — **прямая проверка обещания «уважения ко
  времени игрока»**

Запускается ночью в CI. Отчёт коммитится, изменения баланса видны как diff между
отчётами.

### Инспектор мира

Подключается к живому серверу (локальному или боевому, с правами администратора):
дерево сущностей, значения компонентов, история команд игрока, покадровый разбор
любого боя из реплея.

## Билд-пайплайн

Вкладка **Build** в редакторе.

Список целей, у каждой — кнопка сборки и лог в реальном времени:

```
[✓] Windows x64      → dist/planetwar-win-x64.zip
[✓] Linux x64        → dist/PlanetWar-x86_64.AppImage
[ ] macOS arm64      → требует macOS-машины
[✓] Android arm64    → dist/planetwar.aab
[ ] iOS arm64        → требует macOS + Apple Developer Program
[✓] Server Linux x64 → dist/pw_server
```

Каждая цель — это CMake preset плюс шаги упаковки. Кнопка «Build All» собирает
всё, что доступно на текущей машине.

### Внешние ограничения, которые обойти нельзя

Об этом стоит знать заранее, чтобы не было сюрпризов:

- **macOS и iOS собираются только на Mac.** Нужен Xcode и компилятор
  Metal-шейдеров. Кросс-компиляция с Linux/Windows невозможна — это ограничение
  Apple, а не наше.
- **iOS требует Apple Developer Program**, 99 USD в год. Без него собранное
  приложение нельзя поставить даже на собственный телефон дольше чем на 7 дней.
- **Android требует NDK**, но собирается с любой ОС.
- **Публикация в App Store и Google Play** — отдельные аккаунты разработчика и
  процесс ревью. Для Android есть обходной путь через прямую раздачу `.apk`, для
  iOS — нет.

Практический вывод: **для полного цикла сборки нужна хотя бы одна macOS-машина.**
Пока её нет, четыре платформы из пяти собираются, iOS ждёт.

## Локализация

Все тексты, видимые игроку, — тип `loc_string` в схеме. Редактор показывает
таблицу переводов с колонкой на язык и подсвечивает непереведённое.

Русский и английский — с первого дня. SDF-атлас шрифтов сразу содержит кириллицу
и латиницу; формат атласа рассчитан на добавление CJK без переделки.
